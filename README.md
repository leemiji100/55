# 5조 포켓프렌즈 

## 우리가 포켓프렌즈를 선택한 이유
## 주제

성인을 위한 레트로 감성 다마고치 '포켓 프렌즈' 제작

## 기획 의도

'포켓 프렌즈'는 어린 시절 다마고치를 키우며 즐거웠던 추억을 성인들이 다시 경험할 수 있도록 기획한 레트로 감성 육성 게임이다. 바쁜 일상 속에서 잠시나마 어린 시절의 향수를 느끼고, 귀여운 캐릭터를 돌보며 소소한 즐거움과 힐링을 얻을 수 있도록 제작하였다.

기존 다마고치의 감성을 유지하면서도 현대적인 디자인과 다양한 캐릭터 요소를 더해 추억과 새로운 재미를 동시에 제공하는 것을 목표로 하였다. 또한 디지털 시대에 익숙한 성인들에게 단순한 게임이 아닌 감성적인 경험과 소장 가치를 느낄 수 있는 콘텐츠를 만들고자 하였다.

또한 캐릭터를 스스로 만들고 설정하는 재미를 느낄 수 있게 하였습니다.

# 포켓프렌즈 — Figma Make 프롬프트 세트

Figma Make는 대화형으로 쌓아가는 도구입니다. **STEP 1을 통째로 붙여넣어 뼈대를 만든 뒤, STEP 2~6을 하나씩 추가**하세요. 한 번에 전부 넣으면 후반 요구사항이 누락됩니다.

시작 전 준비: 생성해 둔 시안 6장(01_home ~ 06_chat)을 첨부하고 `"첨부한 이미지의 픽셀아트 스타일과 색감, 레이아웃을 그대로 따라줘"` 를 함께 입력하면 스타일 일치도가 크게 올라갑니다.

## STEP 1 — 뼈대 + 디자인 시스템 + 전역 상태

```
'포켓프렌즈(Pocket Friends)'라는 AI 다마고찌 모바일 앱의 작동하는 프로토타입을 만들어줘.
핵심 컨셉은 "사용자가 AI 캐릭터와 대화를 나눌수록 캐릭터가 성장한다"는 것이고,
이 인과관계가 화면에서 눈에 보이게 만드는 게 가장 중요해.

[화면 규격]
- 모바일 단일 컬럼, 390 x 844, 세로 고정. 데스크탑에서는 가운데 정렬된 폰 프레임 안에 표시.

[아트 디렉션]
- 파스텔 핑크 톤의 아기자기한 픽셀아트 / 코지 게임 UI.
- 모든 카드와 버튼은 radius 16~20, 테두리 2px 실선, 그림자 대신 테두리로 구분.
- 폰트는 둥근 고딕 계열(Pretendard 또는 system-ui), 본문 12~13px, 타이틀 20px Bold.
- 아이콘은 이모지 대신 단순한 도형/SVG로.

[컬러 토큰]
--bg-header:   #FDE7E2
--bg-card:     #FEEFDE
--bg-row:      #FEEADB
--bg-bubble:   #FCEAD7
--border:      #E8948A
--pink:        #F58891
--pink-deep:   #E2698F
--pink-soft:   #FACDC8
--text:        #78585C
--text-muted:  #BC989E
--gauge-mood:   #FE9A99
--gauge-hunger: #FDC987
--gauge-energy: #C2D684
--gauge-empty:  #FDDED6
--room-wall:   #FAD8BB
--room-floor:  #E2A477

[공통 레이아웃]
1. 상단 헤더(고정): 왼쪽에 'Day 12' 알약 배지, 가운데 화면 타이틀, 오른쪽에 코인 '1,250' 배지 + 원형 '+' 버튼.
2. 하단 탭바(고정) 5개: 홈 / 놀아주기 / 옷입히기 / 여행보내기 / 설정.
   활성 탭은 --pink 배경의 둥근 사각형으로 강조.
3. 가운데 콘텐츠 영역은 스크롤.

[전역 상태 - 모든 화면이 공유]
const state = {
  day: 12,
  coins: 1250,
  mood: 80,        // 0~100
  hunger: 70,
  energy: 90,
  bondLevel: 3,    // 교감 레벨
  bondExp: 5,      // 0~8, 8이 되면 레벨업하고 0으로
  chatCount: 128,  // 누적 대화 수
  outfit: 'pink',
  messages: [],    // {role:'user'|'ai', text}
  memories: [],    // 대화에서 추출한 취향 키워드 배열
  tripLog: []
}
상태는 상단 컴포넌트에서 관리하고 모든 화면에 props로 내려줘.
새로고침해도 유지되도록 브라우저 저장소에 저장.

우선 이 구조와 5개 탭 라우팅, 헤더/탭바만 먼저 만들어줘. 각 화면 내용은 빈 상태로 둬.
```

## STEP 2 — 대화 화면 (가장 중요, 먼저 완성)

```
'대화하기' 화면을 만들어줘. 하단 탭에는 없고, 홈 화면의 채팅 입력바를 누르면 열리는 전체화면이야.
헤더 타이틀은 '대화하기', 왼쪽에 뒤로가기 화살표.

[상단 - 교감 카드]
- 왼쪽에 하트 아이콘 + "교감 레벨 {bondLevel}" (Bold 15px)
- 오른쪽에 "다음 레벨까지 대화 {8 - bondExp}번" (11px, --text-muted)
- 아래에 8칸짜리 블록형 진행바. bondExp 만큼 --pink로 채우고 나머지는 --gauge-empty.

[가운데 - 캐릭터]
- 방 배경 위에 캐릭터가 서 있는 영역. 첨부 이미지를 배경으로 써도 되고,
  없으면 --room-wall / --room-floor 로 단순한 방을 그려줘.
- 캐릭터는 bondLevel에 따라 표정이 달라짐(1~2 무표정, 3~4 미소, 5+ 활짝 웃음).

[아래 - 대화 로그]
- 반투명 흰 카드(radius 22) 안에 말풍선 리스트, 새 메시지가 오면 자동으로 아래로 스크롤.
- AI 말풍선: 왼쪽 정렬, --bg-bubble 배경, --border 테두리, --text 글자.
- 사용자 말풍선: 오른쪽 정렬, --pink 배경, 흰 글자, 테두리 --pink-deep.
- 초기 대화 4개를 미리 넣어둬:
  AI "오늘 하루 어땠어?" / 나 "학교에서 발표했어!" / AI "우와 떨렸겠다! 어땠어?" / 나 "끝나고 좀 뿌듯했어"

[하단 - 입력바]
- 둥근 알약 형태 입력창 + 오른쪽 원형 전송 버튼(--pink-deep, 흰 종이비행기).
- placeholder: "포켓프렌즈에게 말을 걸어보세요…"

[대화 엔진 - 실제 API는 호출하지 말고 규칙 기반으로]
사용자가 메시지를 보내면:
1. 사용자 말풍선을 즉시 추가.
2. 0.8초간 '···' 타이핑 인디케이터를 AI 쪽에 표시.
3. 아래 키워드 사전에 맞는 응답을 고르고, 없으면 폴백 배열에서 랜덤 선택.
   - 감정어(기쁘/좋/신나/뿌듯) → "나도 덩달아 기분 좋아졌어! 더 얘기해줘"
   - 감정어(힘들/피곤/속상/슬프) → "많이 힘들었구나… 오늘은 푹 쉬자, 내가 옆에 있을게"
   - 색상어(분홍/파랑/노랑/흰색 등) → "{색}색 좋아하는구나, 기억해둘게!" + memories에 저장
   - 음식어(먹/밥/배고) → "나도 배고파! 뭐 먹었는지 궁금해"
   - 장소어(바다/여행/공원/학교) → "{장소} 좋아하는구나! 나도 가보고 싶다"
   - 폴백: ["그랬구나! 더 얘기해줘", "오, 처음 듣는 얘기야!", "네 얘기 듣는 거 진짜 좋아"]
4. 응답 후 상태 갱신: chatCount +1, bondExp +1, mood +2(최대 100).
   bondExp가 8이 되면 bondLevel +1, bondExp 0으로 리셋하고,
   대화 로그 아래에 "♥ 교감 +3 · 새로운 표정을 배웠어요" 시스템 알림 칩을 하트가 튀어오르는 애니메이션과 함께 표시.
```

## STEP 3 — 홈 화면

```
'홈' 화면을 만들어줘.

- 상단: 기분 / 배고픔 / 에너지 3개 게이지를 한 카드 안에 가로로 나열.
  각 게이지는 5칸 블록형이고 값에 비례해 채움. 색은 토큰의 --gauge-* 사용.
- 그 바로 아래에 작은 칩 2개를 가로로: "♥ 교감 Lv.{bondLevel} · 대화로 자라는 중" / "💬 {chatCount}"
- 가운데: 방 배경 + 캐릭터. 캐릭터 위로 말풍선 2개가 겹치지 않게 표시.
  위쪽 오른쪽에 사용자 말풍선(분홍), 아래쪽 왼쪽에 AI 말풍선(크림, 꼬리가 캐릭터 머리를 향함).
  이 두 말풍선은 messages 배열의 마지막 2개를 그대로 보여줘.
- 하단 탭바 바로 위: 채팅 입력바(알약 형태 + 전송 버튼).
  탭하면 '대화하기' 화면으로 이동. 입력바 자체에서도 바로 타이핑 가능해야 해.
- 캐릭터는 3초마다 살짝 위아래로 떠오르는 idle 애니메이션.
- 30초 동안 입력이 없으면 AI가 먼저 말을 거는 말풍선이 뜸
  ("심심해~ 얘기하자!" / "오늘 무슨 일 있었어?" 중 랜덤).
```

## STEP 4 — 놀아주기 / 옷입히기

```
'놀아주기' 화면:
- 상단에 기분/배고픔/에너지 게이지 카드(홈과 동일 컴포넌트 재사용).
- 가운데 방 배경 + 캐릭터. 위쪽 오른쪽에 사용자 말풍선 "곰돌이랑 놀아줄까?",
  그 아래 왼쪽에 캐릭터 말풍선 "우와~ 신난다!".
- 놀이 카드 4개를 가로로: 공놀이 / 인형놀이 / 노래듣기 / 숨바꼭질. 선택 시 --pink 테두리 + 체크 배지.
- memories 배열에 저장된 취향과 맞는 카드 하나에는 상단에 "AI 추천" 리본을 붙이고,
  탭하면 "어제 재밌다고 했잖아, 또 하자!" 툴팁을 띄워줘.
- 하단에 '놀기 시작' 큰 버튼(--pink). 누르면 3초 미니 애니메이션 후
  mood +10, energy -5, coins +30, bondExp +1. 화면 가운데에 "기분 +10" 플로팅 텍스트가 떠오름.

'옷입히기' 화면:
- 가운데 방 배경 + 캐릭터. 오른쪽 위 사용자 말풍선 "화사한 옷 입고 싶어!",
  그 아래 캐릭터 말풍선 "분홍색 좋아한다고 했지? 기억했어!".
  이 AI 말풍선 문구는 memories에 저장된 색상 키워드를 실제로 반영해서 동적으로 생성해줘.
- 카테고리 탭: 원피스 / 헤어 / 리본 / 신발 / 액세서리.
- 원피스 8종을 4x2 그리드로. 각 카드는 색상 스와치 + 이름. 선택 시 체크 배지.
- memories의 색상과 일치하는 옷 카드에 "AI 추천" 리본.
- 하단에 '기본으로' 버튼과 '입히기' 버튼. '입히기'를 누르면 캐릭터 옷 색이 실제로 바뀌고
  mood +5, 캐릭터가 "예쁘다! 고마워" 말풍선을 띄움.
```

## STEP 5 — 여행보내기 / 설정

```
'여행보내기' 화면:
- 가운데 방 배경 + 캐릭터(여행가방 들고 있음). 오른쪽 위 사용자 말풍선 "바다 보고 싶어!",
  왼쪽 아래 캐릭터 말풍선 "다녀와서 어땠는지 다 얘기해줄게!".
- "어디로 여행을 보낼까요?" 아래 여행지 카드 3개: 꽃밭(30분) / 바닷가(1시간) / 놀이공원(45분).
  각 카드에 소요시간과 '소품 획득' 배지.
- '여행 보내기' 버튼을 누르면 카운트다운이 시작되고(데모용으로 10초로 단축),
  끝나면 tripLog에 기록이 추가되면서 캐릭터가 돌아옴.
- 하단 '다녀온 여행' 리스트. 각 항목에 썸네일 / 여행지명 / 날짜 / '소품 획득' 배지와 함께
  "💬 이야기 듣기" 분홍 칩을 배치.
  이 칩을 누르면 '대화하기' 화면으로 이동하면서
  AI가 그 여행에 대한 이야기를 먼저 3문장 들려주고 bondExp +2를 줘.
  (예: "바닷가에서 조개를 주웠어! 파도 소리가 진짜 시원했어. 다음엔 너랑 같이 가고 싶다")

'설정' 화면:
- 캐릭터가 왼쪽 위에서 "무엇을 바꿀까? 내가 도와줄게!" 말풍선.
- 세로 리스트 6개, 각 행은 아이콘 + 제목(13px Bold) + 설명(9px, --text-muted) + 우측 컨트롤:
  1. 이름 바꾸기 — "나의 이름을 바꿔줘!" — chevron, 탭하면 입력 모달
  2. 알림 — "중요한 소식을 놓치지 않도록!" — 토글 ON
  3. 사운드 — "효과음을 켜고 끌 수 있어!" — 토글 ON
  4. 성격 · 말투 바꾸기 — "어떤 말투로 얘기할까?" — 드롭다운 [다정한 친구 / 씩씩한 동생 / 차분한 언니]
     선택한 값에 따라 대화 엔진의 응답 어미가 실제로 바뀌어야 해.
  5. 추억 보관함 — "우리가 나눈 이야기 다시 보기" — chevron,
     탭하면 memories 배열과 전체 대화 로그를 날짜별로 보여주는 화면으로 이동
  6. 데이터 초기화 — "처음부터 새롭게 시작할 수 있어" — chevron, 확인 모달 후 상태 리셋
- 맨 아래에 "♥ 언제든 필요하면 말해줘! 내가 여기 있을게" 안내 문구.
```

## STEP 6 — 마감 다듬기

```
전체를 다듬어줘.
1. 화면 전환에 200ms fade + 살짝 위로 슬라이드 인 애니메이션.
2. 모든 버튼에 눌림(scale 0.96) 피드백.
3. 게이지 수치가 변할 때 숫자와 블록이 부드럽게 채워지는 트랜지션.
4. 교감 레벨업 순간에는 화면 전체에 하트 파티클이 잠깐 흩날리고
   "교감 레벨 {n} 달성!" 토스트를 띄워줘.
5. 접근성: 모든 탭·버튼에 aria-label, 텍스트 대비 4.5:1 이상 확보.
6. 빈 상태 처리: 대화 로그가 비어 있으면 "먼저 말을 걸어볼까?" 안내와
   추천 문장 칩 3개("오늘 하루 어땠어?" / "뭐하고 놀까?" / "심심해") 표시, 탭하면 바로 전송.
```

④ 기억의 흔적이 없다
5개 화면이 서로 독립적이에요. 이전 대화가 이후 화면에 반영된 증거가 없어서, 대화가 있다 해도 단발성 리액션으로만 보입니다.

과제 목표
이 과제를 마친 후, 학습자는 아래를 스스로 설명할 수 있어야 한다.

1. 텍스트 프롬프트의 구성 요소(스타일, 레이아웃, 색상 등)가 결과물에 미치는 영향

AI 이미지 생성에서는 프롬프트의 구성 요소에 따라 결과물의 분위기와 완성도가 크게 달라진다.

스타일(Style)
'픽셀아트', '도트 그래픽', '치비 캐릭터', '귀여운 모바일 게임 UI' 등의 키워드를 사용하여 전체적인 그래픽 스타일을 결정하였다. 이를 통해 레트로 감성과 아기자기한 게임 분위기를 표현할 수 있었다.
레이아웃(Layout)
'중앙에 캐릭터 배치', '상단 상태바', '하단 네비게이션', '방 안 인테리어' 등의 구성을 프롬프트에 포함하여 실제 모바일 게임 화면과 같은 UI 구조를 생성하였다.
색상(Color)
'파스텔 핑크', '크림톤', '따뜻한 조명' 등의 키워드를 사용하여 전체적으로 부드럽고 공주풍의 분위기를 연출하였다. 색상을 통일함으로써 화면의 일관성과 완성도를 높일 수 있었다.
세부 요소(Detail)
리본, 드레스, 토끼 인형, 보석함, 커튼 등의 소품을 구체적으로 명시하여 캐릭터와 배경이 자연스럽게 어우러지는 공간을 구성하였다.
2. AI 생성 이미지의 문제점(텍스트 깨짐, 부자연스러운 요소)을 식별하고 수정하는 방법

AI가 생성한 UI 이미지는 디자인은 우수하지만 실제 서비스에서 사용하기에는 몇 가지 오류가 발생한다.

텍스트 깨짐
메뉴명이나 버튼의 글자가 의미 없는 문자로 생성되는 경우가 많다.
해결 방법은 AI가 생성한 이미지를 참고용으로 사용하고, Figma나 Photoshop에서 실제 텍스트를 다시 입력하여 수정한다.
아이콘 및 버튼 오류
아이콘의 형태가 일정하지 않거나 버튼 크기가 서로 다른 경우가 발생한다.
후가공 단계에서 아이콘을 교체하고 간격과 정렬을 통일하였다.
비현실적인 UI 구조
버튼 간격이나 터치 영역이 실제 모바일 UX 기준에 맞지 않는 경우가 있다.
디자인 툴에서 Grid와 Auto Layout을 적용하여 모바일 환경에 맞게 재배치하였다.
캐릭터 및 배경의 부자연스러움
손이나 장식의 형태가 어색하거나 배경 오브젝트가 왜곡되는 경우가 발생하였다.
필요한 부분은 직접 수정하거나 여러 번 이미지를 생성하여 가장 자연스러운 결과를 선택하였다.
3. AI 생성 이미지의 일관성을 유지하기 위한 방법

동일한 게임 스타일을 유지하기 위해 다음과 같은 방법을 활용하였다.

시드(Seed) 고정
동일한 시드를 사용하여 캐릭터와 UI 스타일이 크게 변하지 않도록 유지하였다.
이미지 레퍼런스 활용
기존에 생성한 홈 화면을 레퍼런스로 사용하여 다른 화면(놀아주기, 옷 입히기, 여행 보내기, 설정)의 디자인을 생성하였다.
이를 통해 캐릭터 비율과 색감, UI 스타일을 통일할 수 있었다.
프롬프트 반복 사용
핵심 키워드(픽셀아트, 파스텔 핑크, 모바일 게임 UI, 치비 캐릭터 등)를 모든 화면에 동일하게 적용하여 디자인의 일관성을 유지하였다.
후가공을 통한 통일
생성된 이미지를 그대로 사용하지 않고 색상, 폰트, 아이콘, 여백을 디자인 툴에서 수정하여 하나의 서비스처럼 통일감을 높였다.
4. 기획 → 이미지 생성 → 후가공 → 프로토타입으로 이어지는 AI 협업 워크플로우

결과

AI는 초기 시안을 빠르게 제작하는 데 큰 도움이 되었으며, 이후 디자인 툴을 이용한 후가공을 통해 완성도를 높였다. 이러한 기획 → AI 생성 → 후가공 → 프로토타입의 협업 워크플로우를 활용하여 제작 시간은 단축하면서도 디자인의 품질과 일관성을 확보할 수 있었다.

최종(3)



각 수정 단계에서 변경한 이유와 결과 차이를 기록한다


1차 시안(달걀)에서 2차 시안(공주)으로 수정한 이유

1차 시안은 새싹이 달린 달걀 캐릭터를 중심으로 한 심플한 다마고치 콘셉트였습니다. 캐릭터가 귀엽고 직관적이라는 장점은 있었지만, 전체적으로 콘텐츠의 확장성과 사용자의 몰입을 이끌어내기에는 한계가 있었습니다. 이에 따라 단순히 캐릭터를 돌보는 게임이 아니라 사용자가 애정을 가지고 지속적으로 성장시키고 꾸밀 수 있는 육성 게임의 방향으로 콘셉트를 발전시켰습니다.

1. 캐릭터 성장의 재미를 강화하기 위해

1차 시안에서는 캐릭터의 변화 요소가 제한적이어서 장기간 플레이할 동기가 다소 부족했습니다. 이를 보완하기 위해 2차 시안에서는 공주 캐릭터를 중심으로 의상과 액세서리를 변경하고 성장 과정을 시각적으로 표현할 수 있도록 수정했습니다. 사용자는 캐릭터를 키우면서 다양한 모습을 수집하고 꾸미는 재미를 경험할 수 있습니다.

2. 타깃 사용자의 취향을 반영하기 위해

공주풍 일러스트와 파스텔톤 디자인은 캐릭터 꾸미기와 아바타 게임을 선호하는 사용자층에게 친숙한 분위기를 제공합니다. 특히 리본, 드레스, 인형, 핑크 계열의 인테리어를 활용하여 감성적인 분위기를 조성하고, 사용자에게 애착을 형성할 수 있도록 디자인 방향을 변경했습니다.

3. 게임의 목적성을 명확하게 하기 위해

1차 시안은 상태 관리 중심의 UI 비중이 컸다면, 2차 시안에서는 간식 주기, 놀아주기, 목욕하기, 잠재우기처럼 육성 행동을 중심으로 구성하여 사용자가 무엇을 해야 하는지 직관적으로 이해할 수 있도록 개선했습니다. 또한 의상 변경과 여행 등의 콘텐츠를 추가하여 게임 플레이의 목표를 더욱 다양하게 만들었습니다.

4. 화면의 몰입감을 높이기 위해

기존 시안은 여백이 많고 캐릭터가 중앙에만 배치되어 다소 단조로운 느낌이 있었습니다. 2차 시안에서는 방 안의 가구와 소품을 배치하여 실제 캐릭터가 생활하는 공간처럼 연출했습니다. 이를 통해 게임의 세계관을 강화하고 화면을 더욱 풍성하게 구성했습니다.

5. UI의 통일성과 완성도를 높이기 위해

1차 시안은 메뉴마다 컬러가 분산되어 있었지만, 2차 시안에서는 핑크와 크림 계열을 메인 컬러로 통일하여 전체적인 디자인의 일관성을 높였습니다. 또한 픽셀풍 아이콘과 UI 요소를 적용하여 레트로 게임 감성을 더하고, 캐릭터와 인터페이스가 하나의 콘셉트로 자연스럽게 연결되도록 개선했습니다.

6. 플레이 동기를 강화하기 위해

기존에는 상태 수치 확인이 주요 기능이었다면, 수정된 시안에서는 출석(Day), 코인, 의상 수집, 여행 콘텐츠 등을 추가하여 반복 플레이에 대한 보상을 제공하도록 설계했습니다. 이러한 시스템은 사용자가 꾸준히 접속하고 캐릭터를 성장시키려는 동기를 높여줍니다. 그리고 또한 캐릭터를 스스로만들어 몰입감을 주었으며 이를 가장 큰 장점으로 생각합니다.
